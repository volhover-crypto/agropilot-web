# ТЗ: Раздел «Справочники» v2 — НСИ-хаб AgroPILOT

Статус: фазы 1a (beed9cb), 1b (a65e258) и 1d «пользовательские справочники»
(§45.10) РЕАЛИЗОВАНЫ и ЗАДЕПЛОЕНЫ на прод 28.09.2026. Фаза 1c и 2 —
по этому ТЗ. Источник правды по эндпоинтам — CONTRACTS.md §45.

**Дополнительно решено владельцем 28.09.2026 (старт фазы 1a):** сиды регионов —
Российская Федерация (страна + 85 субъектов, города вручную); права —
создание/изменение/архив для всех авторизованных, физическое удаление — только
admin/manager; автокод — префиксный (`ED-0001`).

## 1. Цель и не-цели

**Цель.** Превратить раздел «Справочник» (read-only дерево-архив, контракт §18) в полноценный
инструмент управления нормативно-справочной информацией (НСИ): редактируемые справочники с
аудитом изменений, иерархиями групп и дедупликацией, с сохранением существующего архива как
режима «Навигатор».

**Не-цели (фазы 2+, сознательно вне MVP):**
- импорт/экспорт Excel/CSV (мастер с маппингом и dry-run);
- перевод палитры Ctrl+K на серверный поиск;
- прайс-листы, версии записей с утверждением (workflow);
- drag-n-drop (перемещение между группами — через меню «Переместить»);
- изменение существующих API источников/каналов/сегментов (старые эндпоинты остаются).

**Принятые решения (развилки закрыты 2026-09-28):**
концепция — НСИ-хаб с двумя режимами; состав v1 — унификация существующих + базовые НСИ +
контрагенты + номенклатура; архитектура — гибрид (реальные таблицы PostgreSQL + generic-движок);
MVP-фичи — аудит изменений, иерархии групп, дедупликация.

## 2. Концепция раздела

Один пункт сайдбара «Справочники» (замена текущего «Справочник»), два режима — таб-переключатель:

```
┌─ СПРАВОЧНИКИ ──────────── [НСИ] [Навигатор] ────────────────────┐
│ ┌─дерево типов──┐ ┌─группы──────┐ ┌─таблица──────────────────┐  │
│ │ Базовые       │ │ ▸ Все       │ │ Код │ Наименование │ Ед │…│  │
│ │  Единицы      │ │ ▾ Овощи     │ │ 001 │ …            │ кг │  │
│ │  Валюты       │ │   ▾ Корнепл │ │     │              │    │  │
│ │  Регионы      │ │ ▸ Зелень    │ │ [+ Создать] [⋯ Архив]    │  │
│ │ Маркетинг     │ └─────────────┘ └──────────────────────────┘  │
│ │  Источники …  │  Поиск: [______]  Статус: [Активные ▾]        │
│ │ Партнёры      │  Показано 25 из 214 ◂ 1 2 3 … ▸               │
│ │  Контрагенты  │                                                 │
│ │ Номенклатура  │                                                 │
│ └───────────────┘                                                 │
└──────────────────────────────────────────────────────────────────┘
```

- **Режим «НСИ»** — редактируемые справочники (новый функционал, ядро ТЗ).
- **Режим «Навигатор»** — существующий read-only архив-дерево (vCatalog, контракт §18),
  переносится как есть; роут `#/catalog` остаётся рабочим и открывает этот режим.
- Попутные фиксы Навигатора (в рамках фазы 1a): разрешение `owner` id → имя в превью;
  debounce поиска и сброс состояния при выходе из раздела; индикатор «показано N из total».

## 3. Состав справочников v1

| Группа | Справочник | Тип | Иерархия | Предопределённые (is_system) |
|---|---|---|---|---|
| Базовые | Единицы измерения `units` | новый | нет | шт, кг, т, л, м, м², ч, усл.ед. |
| Базовые | Валюты `currencies` | новый | нет | KZT, USD, RUB, EUR |
| Базовые | Регионы/гео `regions` | новый | да (страна→область→город) | РФ + 85 субъектов (решение 28.09) |
| Базовые | Теги `tags` | новый | нет | — |
| Маркетинг | Источники `sources` | адаптер существующих | по type | коннекторы (O2) |
| Маркетинг | Каналы `channels` | адаптер существующих | нет | — |
| Маркетинг | Сегменты `segments` | адаптер существующих | нет | — |
| Партнёры | Контрагенты `contractors` | новый | нет (групп через теги нет) | — |
| Номенклатура | Номенклатура `nomenclature` | новый | да (группы+элементы, 1С-стиль) | — |

Поля новых справочников:

- **units**: code, name*, symbol*, kind (enum: шт/вес/объём/длина/площадь/время/усл), intl_code (ОКЕИ).
- **currencies**: code (ISO-4217)*, name*, symbol, minor_unit (int, кратность копеек).
- **regions**: code, name*, level (enum: country/region/city), parent_id FK self RESTRICT.
- **tags**: name*, color (hex), описание.
- **contractors**: code, name_full*, name_short, kind (enum: юрлицо/ИП/физлицо)*, bin_iin,
  bank_name, bic_iban, account, legal_address, region_id FK regions RESTRICT, phone, email,
  website, comment.
- **nomenclature**: code, article, name*, kind (enum: товар/услуга)*, unit_id FK units RESTRICT*,
  vat_rate (numeric), price_base numeric + currency_id FK currencies, is_group bool
  (группа не имеет unit/price).

`*` — обязательное. Для существующих (sources/channels/segments) состав полей берётся из их
фактических моделей на фазе 1c через field_map (спека ниже), их таблицы не переделываются.

## 4. Архитектура backend — гибрид

Принцип: **реальная таблица PostgreSQL на каждый новый справочник** (целостность, FK, UNIQUE,
статистики планировщика) + **generic-движок в коде** (единый CRUD/аудит/пагинация/дедуп поверх
декларативного реестра SPEC). EAV не используется; JSONB — только для расширяемых атрибутов
(`attrs`) и аудита (diff).

### 4.1. Модуль `backend/catalogs/`

```
backend/catalogs/
  __init__.py
  registry.py   # SPEC: декларативные описания всех справочников (поля, валидации, уникальность)
  models.py     # SQLAlchemy-модели: CatalogMixin (служебные колонки) + Unit, Currency, Region,
                # Tag, Contractor, NomenclatureItem
  engine.py     # generic: list/get/create/update/archive/restore/delete/merge/duplicates,
                # пагинация+фильтры+сортировка, валидация по SPEC, вызов аудита
  audit.py      # diff old/new → catalog_audit, чтение истории
  routes.py     # FastAPI-роутер /agropilot/api/v1/catalogs/*
```

### 4.2. SPEC (registry.py)

```python
CATALOGS = {
  "units": {
    "title": "Единицы измерения", "group": "Базовые",
    "model": "Unit", "hierarchical": False,
    "code_prefix": "ED",                    # автонумерация ED-0001, редактируем после создания
    "edit_roles": ["manager", "engineer"],  # enforced в backend, дефолт ["manager"]
    "fields": [
      {"key": "code",      "type": "string", "grid": True, "width": 90},
      {"key": "name",      "type": "string", "required": True, "unique": True, "grid": True},
      {"key": "symbol",    "type": "string", "required": True, "grid": True},
      {"key": "kind",      "type": "enum", "options": [...], "grid": True},
      {"key": "intl_code", "type": "string"},
    ],
    "dup_fields": ["name", "symbol"],       # кандидаты на дедуп
  },
  "sources": {                              # адаптер существующих
    "title": "Источники", "group": "Маркетинг", "model": "Source",
    "adapter": True, "field_map": {...},    # маппинг на фактические колонки (фаза 1c)
    "refs": [{"table": "content", "column": "source_id"}],  # для merge
  },
  ...
}
```

### 4.3. API (единый префикс `/agropilot/api/v1/catalogs`)

| Метод и путь | Назначение |
|---|---|
| `GET /catalogs` | реестр типов + полная схема полей (фронт рендерит UI из этого) |
| `GET /catalogs/{t}?q=&status=&parent=&sort=&limit=&offset=` | список; ответ `{items, total, limit, offset}` |
| `POST /catalogs/{t}` | создать (автокод, unique-проверка, dup-предупреждение как warning) |
| `GET /catalogs/{t}/{id}` | запись |
| `PATCH /catalogs/{t}/{id}` | изменить; diff пишется в аудит |
| `POST /catalogs/{t}/{id}/archive` / `restore` | мягкое удаление / возврат |
| `DELETE /catalogs/{t}/{id}` | физическое удаление; только для записей без ссылок (FK RESTRICT → 409 с читаемым объяснением) |
| `GET /catalogs/{t}/{id}/history` | журнал изменений записи |
| `GET /catalogs/{t}/duplicates?q=` | fuzzy-кандидаты (pg_trgm similarity, топ-5) |
| `POST /catalogs/{t}/merge` | `{target_id, source_ids[]}`: перенос ссылок из SPEC.refs, архив дублей, аудит |

Общие правила: неизвестный `{t}` → 404; `{t}` без прав на запись → 403; `is_system`-записи —
только чтение (изменение name допустимо, удаление/архив — нет); пагинация limit ≤ 200, дефолт 50;
сортировка `sort=-code` (минус — desc).

### 4.4. Аудит

Таблица `catalog_audit` (append-only, общая для всех справочников):
`entity TEXT, entity_id BIGINT, action TEXT (create/update/archive/restore/delete/merge),
diff JSONB ({поле: {old, new}}), user_id, user_name, created_at` + индекс `(entity, entity_id, id DESC)`.
Пишется движком на каждую мутацию (модель Frappe `Version`). UI — таймлайн в карточке.
Откат = создание новой версии со старыми значениями (не удаление строк журнала).

### 4.5. Дедупликация и слияние

- `CREATE EXTENSION IF NOT EXISTS pg_trgm` + GIN-индексы по dup_fields (`gin_trgm_ops`).
- `GET /duplicates?q=` → `similarity(name, q) >= 0.35 OR name ILIKE %q%`, топ-5, с коэффициентом.
- Merge: значения полей дубля не перезаписывают целевую запись (целевая — golden record),
  ссылки из `SPEC.refs` переносятся UPDATE'ами, дубли архивируются, операция — одна запись аудита.

### 4.6. Роли (решение 2026-09-28)

Создание/изменение/архив/восстановление — все авторизованные; физическое
удаление (и merge в 1b) — admin/manager (`SPEC.delete_roles`). Токен ролей не
несит (`deps.py`), enforcement в движке: `sub` → `team.role_key`. Чтение —
любой авторизованный. Фронт скрывает кнопку удаления (по `isManager()`),
сервер — источник правды.

## 5. Модель данных (миграции, продолжают ряд после 040)

- **041_nsi_core.sql** — `catalog_audit`, `units`, `currencies`, `regions`, `tags` + сиды
  предопределённых (is_system=true) + pg_trgm. Идемпотентно (`IF NOT EXISTS`).
- **042_contractors.sql** — `contractors`.
- **043_nomenclature.sql** — `nomenclature` (self-FK parent_id RESTRICT, is_group).
- **044_nsi_existing.sql** — фаза 1c: additive-колонки служебных полей для `sources/channels/segments`
  (`code`, `status` при отсутствии) — только ALTER TABLE ADD, данные не трогаем.

Общие служебные колонки всех новых таблиц (CatalogMixin):

```sql
id BIGSERIAL PRIMARY KEY,
code TEXT NOT NULL UNIQUE,            -- ED-0001: prefix + seq, человекочитаемый ключ
name TEXT NOT NULL,
is_system BOOLEAN NOT NULL DEFAULT false,
status TEXT NOT NULL DEFAULT 'active' CHECK (status IN ('active','archived')),
sort_order INT NOT NULL DEFAULT 0,
attrs JSONB NOT NULL DEFAULT '{}',    -- расширяемые атрибуты без миграций
created_by BIGINT, created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
updated_by BIGINT, updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
-- parent_id, is_group — только у иерархических
```

Принципы: никаких физических DELETE записей, на которые есть FK (RESTRICT сам скажет 409);
архив вместо удаления; уникальность — DB-констрейнтом, а не только кодом.

## 6. Frontend

### 6.1. Структура и метадата-driven UI

- Новый файл `js/app.catalogs.js` — отдельный Alpine-компонент `catalogs` (~свой state/render/bind);
  `app.objects.js` не разрастается: роутер `go('catalogs')` рендерит контейнер и инициализирует
  компонент; события навешиваются по живому блоку `bindView()` (app.objects.js:5818 — помним,
  блок :524 мёртвый).
- Фронт один раз запрашивает `GET /catalogs` и **генерирует** дерево типов, таблицы, формы,
  валидацию и фильтры из схемы SPEC — новый справочник на бэкенде автоматически получает UI.
  Escape hatch: поле SPEC `render: "custom"` подключает ручной рендер для нестандартных экранов.

### 6.2. Таблица (грид)

Must-have v1: sticky-заголовок; сортировка по колонкам (клик); глобальный поиск с debounce 300 мс;
фильтр статуса актив/архив; пагинация «показано N из M» (limit 50, кнопки ◂ ▸); чекбоксы строк →
панель bulk-действий (архивировать/восстановить); кнопки строки: ✎ изменить, ⟳ история, ⋯ меню
(переместить в группу / архивировать / удалить); состояние таблицы (sort/фильтры) в localStorage.
Виртуальный скролл и inline-редактирование — фаза 2.

### 6.3. Формы записей

- Справочники ≤ 6 полей — модалка (`openModal`, существующий паттерн).
- Контрагенты, номенклатура (7+ полей) — drawer (боковая панель справа, чистый CSS, без
  зависимостей): виден контекст таблицы, кнопка «Сохранить и новая» для массового ввода.
- Валидация: required/типы/enum из SPEC на клиенте + маппинг серверных ошибок на поля.
- **Дубликаты при создании**: после ввода наименования (debounce) → `GET /duplicates` → панель
  «Похожие записи» (топ-3: имя + коэффициент) с [Открыть] / [Всё равно создать].

### 6.4. Иерархии (regions, nomenclature)

Дерево групп слева + таблица справа; хлебные крошки (текущая группа + «Все элементы»);
«перетащить» нельзя — перемещение через меню строки «Переместить в группу» (модалка с деревом);
защита от циклов родства (уже есть эталон `_assert_parent_ok` в artifacts/routes.py:57-71);
на < 1024px дерево сворачивается.

### 6.5. Обвязка фронтенда

- `js/api.js`: `AGL.catalogSpecs()`, `catalogList(type, params)`, `catalogCreate/Update/Archive/
  Restore/Delete/History/Duplicates/Merge` — по образцу существующих методов, через `apiFetch`.
- Демо/mock-режим: mock-набор для базовых справочников + guard `apiMode` на мутациях
  («В демо-режиме недоступно», паттерн Артефактов); пустые состояния с кнопками «Создать».
- Тосты — существующий `$toast` (ui-reka.js).
- Кэш: после каждой мутации — re-fetch текущего списка (паттерн Артефактов); счётчики дерева
  типов обновляются тем же ответом.

## 9. Риски и открытые вопросы

- **Два `bindView()`** в app.objects.js (:524 мёртвый, :5818 живой) — новый код в app.catalogs.js
  от этой мины изолирован; при правках app.objects.js не наступать на :524.
- **pg_trgm** — расширение системного уровня; если владелец БД не даст — fallback дедупа на
  ILIKE + Levenshtein в Python (медленнее, но работает).
- **Кириллица + pg_trgm** — работает из коробки; проверить similarity-порог 0.35 на реальных
  данных (наименования номенклатуры).
- **Открытые вопросы фазы 1a — ЗАКРЫТЫ 28.09.2026 владельцем:**
  1) сиды регионов — Российская Федерация (+ 85 субъектов);
  2) права — создание/изменение/архив всем, удаление только admin/manager;
  3) автокод — префиксный (`ED-0001`).
